# 扫码授权、分享与剪贴板

[项目首页](../README.md) · [安装说明](INSTALL.md) · [安全说明](../SECURITY.md)

## 使用入口

“我的 → 扫码授权登录”用于以当前主账号授权你本人设备的网页或 TV 登录二维码；登录页显示二维码用于登录 Pili--，两者用途不同。扫一扫的相机与相册均可识别登录码，进入独立原生确认页后核对账号、目标应用和服务端登录位置，再明确点击授权。异地提醒需额外确认。

“我的 → 识别链接”可手动输入或主动粘贴分享文案、B 站内容链接、b23.tv 及 BV/av 号。扫一扫右上角也有入口。多个链接逐项展示，点击选择后打开；短链接在用户选择打开后才联网解析。

Android 可从其他 App 的系统分享面板选择 Pili--，支持纯文本分享。冷启动与已运行时都接收，文本和事件队列仅保存在进程内，消费后清理 Intent；不会自动打开链接或授权登录。

## 开关与读取边界

| 设置 → 隐私设置 | 默认行为 |
| --- | --- |
| 接收其他 App 分享的 B 站链接 | 开启；关闭后忽略收到的分享 |
| 自动识别剪贴板中的 B 站链接 | 关闭；开启后应用进入前台时读取，确认后打开 |

手动“从剪贴板粘贴并识别”仅在点击时读取，不需要开启自动识别。禁用自动识别时不为此功能读取系统剪贴板；系统自身文本编辑菜单的粘贴由用户主动操作。相同剪贴板内容去重，读到结果后若已关闭开关或退出前台则不提示。扫码、授权和手动输入页面不主动触发自动剪贴板提示。

这些功能不持久化分享正文、剪贴板正文或登录码，不上传到项目服务器。B 站账号资料仍沿用已有账号存储实现；“不持久化登录码”不等于账号凭据从不存储。

## 授权支持与限制

支持当前 `account.bilibili.com/h5/account-h5/auth/scan-web`、旧版 Passport 网页码和已核对的 TV/HD 授权码。严格验证 HTTPS 主机、路径、密钥及重复参数，忽略二维码提供的回调地址；普通分享识别不接收登录授权链接。

确认请求只发往固定的 Passport 官方端点，绑定扫码时的账号，不跨源重定向、不自动重试写请求，不把远端登录返回的 Cookie 安装到当前账号。关闭、过期或账号变化后不再提交；已经发出的授权无法通过关闭页面撤回。若网络超时，先到待登录设备核对结果，避免重复授权。

官方要求手机号或未实现的设备环境验证时会停止原生授权，提示通过官方 App 完成；不会跳过校验。官方接口可能变化，真实账号端到端授权仍需同版本安装包验证。

## 契约参考与验证

仅参考官方公开前端的数据契约，自行实现 Flutter 页面与请求，未打包官方 JS。参考 [account-h5 入口脚本](https://s1.hdslb.com/bfs/static/2233-monorepo/account-h5/static/js/index.eb5c0d23.js)、[当前扫码页面](https://s1.hdslb.com/bfs/static/2233-monorepo/account-h5/static/js/async/542.dae0ac19.js)、[接口声明](https://s1.hdslb.com/bfs/static/2233-monorepo/account-h5/static/js/async/2202.d6259a17.js)及 Passport 旧版页面。

只读研究下载了公开静态资源，并匿名检查官方生成二维码的 URL 格式；没有保存生成密钥、执行真实账号扫码授权或读取用户凭据。自动测试使用假账号和响应适配器，不能代替真实账号授权验收。构建与设备范围见 [验证记录](VALIDATION.md)。
