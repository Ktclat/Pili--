## Pili-- 和 PiliPlus 是什么关系？

Pili-- 基于 PiliPlus，由 Ktclat 独立开发、发布和提供支持，与上游维护团队无隶属关系。本仓库保留继承代码的许可、版权和署名。[PiliPlus](https://github.com/bggRGjQaUbCoE/PiliPlus) · [维护者](https://github.com/Ktclat) · [致谢与来源](ACKNOWLEDGEMENTS.md) · [NOTICE](../NOTICE)

## GitHub Contributors 是维护者名单吗？

GitHub 根据提交历史自动生成 Contributors。当前维护者见仓库首页，继承代码的来源见署名文件。[仓库首页](../README.md) · [NOTICE](../NOTICE)

## 到哪里下载？为什么更新检查没有新版本？

最近的预发布版 `0.6.0+7` 包含悬浮导航更新。发布页提供三个架构的测试签名 APK、校验值与对应源码。覆盖安装需要新旧包使用同一签名。[v0.6.0-beta.1 下载页](https://github.com/Ktclat/Pili--/releases/tag/v0.6.0-beta.1) · [安装说明](INSTALL.md)

应用内只检查稳定 Release，会忽略本次预发布，因此需要手动下载。开发包仍可从成功的 [Actions 运行](https://github.com/Ktclat/Pili--/actions/workflows/build.yml) 获取，Actions 附件有保留期限；也可按 [构建指南](BUILD.md) 自行构建。GitHub 网络不可达或 API 限制也会影响下载和更新检查。上游的 Release 不是 Pili-- 的发布版本。

## 可以和 PiliPlus 同时安装吗？

可以。Pili-- 的 Android 应用 ID 是 `io.github.ktclat.piliminus`，PiliPlus 的是 `com.example.piliplus`。两者可同时安装，账号、设置和默认离线目录相互独立。可在 Android 的「应用 → 默认打开方式」里选择处理 B 站链接的客户端。[共存说明](COEXISTENCE.md)

## 为什么源码里仍然出现 `PiliPlus` 或 `com.example.piliplus`？

应用显示名称、Android applicationId、Dart package 名称和原生代码 namespace 是不同层次的标识。当前源码保留部分上游内部名称，用于兼容现有导入、原生绑定和平台代码；Android 对外安装身份由构建配置中的 applicationId 决定。

## 旧版会员购和 UP 小店去哪了？

从 0.4.0 起已移除，后续维护聚焦视频、社区、扫码、下载和独立应用共存。商品浏览、商品收藏与足迹、商品分享以及相关入口和设置均不再提供，也不计划在客户端实现购物车、订单或支付。

启动时清理相关旧商品数据和开关；视频收藏、播放历史、账号和下载记录保留。升级会忽略旧导航中的已删除项目，保留其余导航的顺序；若只剩已删除项目，则恢复默认导航。安装与签名限制见 [升级说明](INSTALL.md)。

## 悬浮底栏为什么拖动后没有立刻切页？

0.6.0 将拖动预览和页面切换分开：选中背景跟手移动，在目标项停稳约 200 毫秒才切页；快速划过或提前松手会取消待切换。普通点击仍直接切页，同一项的点击沿用原有回顶／刷新行为。

可在“设置 → 外观设置 → 悬浮底栏”即时切换样式。0.6.0 默认启用，但会保留此前明确关闭的偏好；横屏或平板仍使用原有侧栏。入口、取消条件和设计参考见 [悬浮导航说明](FLOATING_NAVIGATION.md)。这些改动不包含在 0.5.0 下载包中，实际验证范围以 [验证记录](VALIDATION.md) 为准。

## 扫码登录与扫码授权有什么不同？

要登录 Pili--，用已登录的客户端扫描 Pili-- 登录页显示的二维码。要为自己的网页或 TV 登录，从首页或「我的」右上角打开「扫一扫」，扫描待登录设备的二维码，再核对账号和登录位置并确认。也可以从相册选取登录码。

授权前需登录 Pili--。遇到手机号或设备验证时，请按提示使用官方 App。请求超时后先到待登录设备查看结果。

## 如何接收分享或识别剪贴板？

Android 分享面板选择 Pili--，可识别纯文本分享里的 B 站内容链接、b23.tv 或 BV/av，先确认再打开。支持冷启动和已打开应用时接收。开关在“设置 → 隐私设置 → 接收其他 App 分享的 B 站链接”，默认开启；关闭后忽略收到的分享。

「自动识别剪贴板中的 B 站链接」默认关闭。开启后，应用回到前台时会识别并提示。要手动识别，点「扫一扫」右上角的链接图标，输入或粘贴文字即可。常用此功能时，可在「设置 → 外观设置 → 右上角按钮」勾选「识别链接」。网页和 TV 登录链接请使用「扫一扫」中的「粘贴登录链接」。

## 支持 iOS、Windows、macOS 或 Linux 吗？

当前构建和发布平台为 Android。仓库保留其他平台的上游源码，欢迎提供适配改动或附设备、系统与复现步骤的问题报告。

## 这是离线或“完全不联网”的客户端吗？

视频、账号、动态等业务需要连接哔哩哔哩 API 与内容 CDN，更新检查连接 GitHub。空降助手、WebDAV 等可选功能还可能使用相应第三方或用户配置的服务。更完整的数据行为与检查边界见[安全说明](../SECURITY.md)。

二维码由设备上的模型识别，打开结果后会访问对应服务。

## 关于页显示 `SNAPSHOT`、`N/A` 或构建时间“未记录”怎么办？

这些字段取决于构建时传入的 `pili.name`、`pili.code`、`pili.hash`、`pili.time`。缺少参数时会使用源码中的默认值；APK 的版本信息和关于页显示也需要保持一致。

当前 [构建脚本](../scripts/build_android.ps1) 会自动从版本文件和 Git 写入这些元数据，未提交修改会附加 `-dirty`；手动执行原始 Flutter 命令时可能缺少参数。请按 [构建指南](BUILD.md) 操作，反馈问题时提供实际提交号。保留的历史验收包没有嵌入提交号，这一限制已记在[验证记录](VALIDATION.md)中，不能据此把它标注为新提交的验证产物。
