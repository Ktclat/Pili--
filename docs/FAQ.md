## Pili-- 和 PiliPlus 是什么关系？

Pili-- 是基于 [PiliPlus](https://github.com/bggRGjQaUbCoE/PiliPlus) 的个人兴趣衍生项目，用于学习、自用和功能实验，当前由 [Ktclat](https://github.com/Ktclat) 独立维护。基础代码和大量功能继承自上游，后续改动在本仓库跟踪。

Pili-- 的开发、发布与用户支持由本仓库独立负责，不是 PiliPlus、PiliPala 或 PiliPalaX 团队发行的版本，与这些上游维护团队无隶属、合作或背书关系。上游作者不因代码被继承而自动成为本项目的维护者。

独立维护不表示从零编写，也不改变继承代码的许可和版权。PiliPala、PiliPalaX 等早期项目及其他开源依赖的来源见[致谢与来源](ACKNOWLEDGEMENTS.md)与 [NOTICE](../NOTICE)。

不是。GitHub 依据提交记录生成贡献者统计，它不代表当前维护团队、合作关系或用户支持责任，也不能直接作为一份项目成员名单编辑。历史整理后的统计更新由 GitHub 处理，本项目不承诺它会立即清空或刷新。

项目来源以 [NOTICE](../NOTICE)、[来源说明](ACKNOWLEDGEMENTS.md)、许可证和文件内版权声明为准；整理历史或创建新的源码快照，不会取消这些署名与许可义务。

## 到哪里下载？为什么更新检查没有新版本？

当前版本 `0.5.0+6` 可从 [v0.5.0-beta.1 预发布页](https://github.com/Ktclat/Pili--/releases/tag/v0.5.0-beta.1) 下载三架构 APK、校验值与对应源码。本次使用测试签名，不保证覆盖旧测试包；架构、签名和下载步骤见 [安装说明](INSTALL.md)。

应用内只检查稳定 Release，会忽略本次预发布，因此需要手动下载。开发包仍可从成功的 [Actions 运行](https://github.com/Ktclat/Pili--/actions/workflows/build.yml) 获取，Actions 附件有保留期限；也可按 [构建指南](BUILD.md) 自行构建。GitHub 网络不可达或 API 限制也会影响下载和更新检查。上游的 Release 不是 Pili-- 的发布版本。

## 可以和 PiliPlus 同时安装吗？

Pili-- 的 Android 应用 ID 是 `io.github.ktclat.piliminus`，与上游使用的身份区分开，应用数据也不会自动迁移。独立包名提供了分别安装的基础，但不等于所有共存行为已经验证。

链接默认打开方式、桌面快捷方式、不同变体和签名更新等，需要按具体版本确认。请查看[验证记录](VALIDATION.md)，遇到问题时注明两个客户端的版本与触发入口。不要为排查问题先卸载并丢失原应用数据。

## 为什么源码里仍然出现 `PiliPlus` 或 `com.example.piliplus`？

应用显示名称、Android applicationId、Dart package 名称和原生代码 namespace 是不同层次的标识。当前源码保留部分上游内部名称，用于兼容现有导入、原生绑定和平台代码；Android 对外安装身份由构建配置中的 applicationId 决定。

仅修改文档不应批量替换源码名称。确需重命名时，要同步检查原生绑定、Manifest、快捷方式和最终安装包，不能靠字符串替换推断已经完成独立适配。

## 旧版会员购和 UP 小店去哪了？

从 0.4.0 起已移除，后续维护聚焦视频、社区、扫码、下载和独立应用共存。商品浏览、商品收藏与足迹、商品分享以及相关入口和设置均不再提供，也不计划在客户端实现购物车、订单或支付。

启动时清理相关旧商品数据和开关；视频收藏、播放历史、账号和下载记录保留。升级会忽略旧导航中的已删除项目，保留其余导航的顺序；若只剩已删除项目，则恢复默认导航。安装与签名限制见 [升级说明](INSTALL.md)。

## 扫码登录与扫码授权有什么不同？

登录页面显示二维码，是用其他已登录客户端为 Pili-- 登录；“我的 → 扫码授权登录”则用 Pili-- 的当前账号，为你本人设备上的网页或 TV 登录码授权。相机和相册均可识别；会进入原生确认页，先核验账号、有效性和登录位置，再由用户明确点击授权。

未登录时需先登录并重新扫码。遇到官方要求的手机号或环境校验时停止原生授权，提示使用官方渠道处理。网络超时可能导致授权结果未知，应先查看待登录设备，不自动重复提交。不要为陌生人提供的登录码授权。

普通扫码仍支持视频链接、BV/av、相册和手电筒。拒绝相机权限后可用相册识别，用户主动点击重试才重新申请相机权限。真实账号授权与真机相机表现需要同版本安装包验收。

## 如何接收分享或识别剪贴板？

Android 分享面板选择 Pili--，可识别纯文本分享里的 B 站内容链接、b23.tv 或 BV/av，先确认再打开。支持冷启动和已打开应用时接收。开关在“设置 → 隐私设置 → 接收其他 App 分享的 B 站链接”，默认开启；关闭后忽略收到的分享。

“自动识别剪贴板中的 B 站链接”默认关闭。开启后在应用进入前台时读取并提示，不自动打开。手动入口在“我的 → 识别链接”或扫一扫右上角；点击“从剪贴板粘贴并识别”只在该次操作读取，不受自动开关影响。登录授权链接不作为普通内容分享打开，请使用扫码授权入口。

## 支持 iOS、Windows、macOS 或 Linux 吗？

仓库保留这些平台的上游源码，当前维护和验收重点是 Android。存在平台目录不代表已经构建、验证或发布对应安装包。

如果你希望参与其他平台适配，请先说明设备、系统、构建环境和实际问题；具体支持状态以该平台的验证记录与发布说明为准。

## 这是离线或“完全不联网”的客户端吗？

视频、账号、动态等业务需要连接哔哩哔哩 API 与内容 CDN，更新检查连接 GitHub。空降助手、WebDAV 等可选功能还可能使用相应第三方或用户配置的服务。更完整的数据行为与检查边界见[安全说明](../SECURITY.md)。

二维码识别本身使用随 APK 提供的模型，本地识别不等于打开识别结果也不联网。收紧部分请求边界也不构成对所有依赖、原生二进制和实时网页的完整审计结论。

## 关于页显示 `SNAPSHOT`、`N/A` 或构建时间“未记录”怎么办？

这些字段取决于构建时传入的 `pili.name`、`pili.code`、`pili.hash`、`pili.time`。缺少参数时会使用源码中的默认值；APK 的版本信息和关于页显示也需要保持一致。

当前 [构建脚本](../scripts/build_android.ps1) 会自动从版本文件和 Git 写入这些元数据，未提交修改会附加 `-dirty`；手动执行原始 Flutter 命令时可能缺少参数。请按 [构建指南](BUILD.md) 操作，反馈问题时提供实际提交号。保留的历史验收包没有嵌入提交号，这一限制已记在[验证记录](VALIDATION.md)中，不能据此把它标注为新提交的验证产物。
